## ✅ 정답 및 풀이

---

**[이론 1] 정답: (B)**

풀이:
1. 기본값 매개변수는 일반(필수) 매개변수보다 **뒤에** 위치해야 합니다. 앞에 두면 `SyntaxError`가 발생합니다.
   ```python
   def f(a=1, b):  # ❌ SyntaxError
   def f(a, b=1):  # ✅ 정상
   ```
2. (A)는 옳습니다. 기본값이 있으면 호출 시 해당 인수를 생략할 수 있습니다.
3. (C)는 옳습니다. 예를 들어 `def f(lst=[]):`처럼 mutable 기본값을 쓰면 모든 호출이 같은 객체를 공유해 버그가 생깁니다.
4. (D)는 옳습니다. 기본값은 함수 호출 시마다가 아니라 `def` 문이 실행될 때 딱 한 번 평가됩니다. (C)의 버그 원인이기도 합니다.)

---

**[이론 2] 정답: `*args` / `**kwargs`**

풀이:
1. `*args`는 위치 인수를 **튜플**로 묶어서 받습니다.
2. `**kwargs`는 키워드 인수를 **딕셔너리**로 묶어서 받습니다.
3. 두 개를 함께 쓸 때는 순서가 중요합니다: `def f(*args, **kwargs):`
4. `*`와 `**`는 언패킹 연산자이기도 합니다 — `f(*[1,2,3])`처럼 호출 시에도 사용할 수 있습니다.

---

**[이론 3] 정답: (C) ①②③④**

풀이:
1. **①** `return`이 없는 함수는 암묵적으로 `None`을 반환합니다. ✅
2. **②** `return`은 함수 내 여러 곳에 사용할 수 있으며, 처음 만나는 `return`에서 함수가 종료됩니다. ✅
3. **③** `return a, b`는 파이썬이 `(a, b)` 튜플로 자동 패키징하여 반환합니다. ✅
4. **④** `return` 이후의 코드는 **dead code**로, 절대 실행되지 않습니다. ✅

**[심화 2] 정답 (수정된 코드):**

```python
def add_item(item, container=None):  # 수정 1: mutable 기본값 → None으로 교체
    if container is None:
        container = []
    container.append(item)
    return container

def multiply(a, b):
    result = a * b
    return result  # 수정 2: return 누락 추가

print(add_item("x"))   # ['x']
print(add_item("y"))   # ['y']  (독립된 리스트)
print(multiply(3, 4))  # 12
```

풀이:
1. **버그 1**: `container=[]`는 함수 정의 시 단 한 번 생성된 리스트 객체를 모든 호출이 공유합니다. 첫 호출 후 `["x"]`, 두 번째 호출 후 `["x", "y"]`가 됩니다. 해결법은 기본값을 `None`으로 두고 함수 내에서 새 리스트를 생성하는 것입니다.
2. **버그 2**: `multiply`에 `return`이 없어 `None`이 반환됩니다. `return result`를 추가해야 합니다.

**[심화 3] 정답:**

```
빈칸 A: *args, **kwargs
```

풀이:
1. `*args`가 위치 인수 `(1, 2, 3)`을 튜플로 수집합니다.
2. `**kwargs`가 키워드 인수 `{'name': 'Alice', 'age': 20}`을 딕셔너리로 수집합니다.
3. 둘을 함께 받을 때 반드시 `*args`가 `**kwargs`보다 앞에 와야 합니다.

**[심화 4] 정답:**

```python
def safe_divide(a, b):
    return "division by zero" if b == 0 else a / b
```

풀이:
1. 파이썬 **조건 표현식(삼항 연산자)** 문법: `참일_때_값 if 조건 else 거짓일_때_값`
2. `b == 0`이면 `"division by zero"` 문자열 반환, 그렇지 않으면 `a / b` 결과 반환
3. 일반 `if`문과 완전히 동일한 동작을 한 줄로 표현한 것입니다.
